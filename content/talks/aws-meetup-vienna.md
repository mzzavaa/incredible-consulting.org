## The services doing the work

Read off the slides, not guessed. Each card says what that service did in this build, and links to the page explaining the capability and how to run it somewhere else.

### AWS CloudFormation

The infrastructure as code itself: resources described in a template rather than clicked together in the console.

### AWS CodeCommit

Version control for the templates, which is what turns a change into something you can review and roll back.

### AWS CodeBuild

Builds and validates on every commit.

### AWS CodeDeploy

Deploys through the pipeline, so the console is no longer the way changes reach production.

### Amazon CloudWatch

Logging and monitoring, so an issue is visible before someone reports it.

### AWS CloudTrail

The record of who changed what.

### AWS Config

Watches the configuration for drift away from the template.

### AWS X-Ray

Traces a request through the pieces when something is slow.

### Amazon Rekognition

Object detection on second-hand clothing photos, then Custom Labels for the categories the ready-made model does not know.

- [Image recognition](https://www.lindamohamed.com/image-recognition-object-detection)

### Amazon SageMaker Ground Truth

Labels the training data without building a labelling tool first.

- [Your own model](https://www.lindamohamed.com/training-and-serving-your-own-model)

### Amazon SageMaker

Training, and the Jupyter and Studio environment the model was built in.

- [Your own model](https://www.lindamohamed.com/training-and-serving-your-own-model)

### AWS Lambda

Triggers the labelling run when a new photo arrives. No servers and no user interface anywhere in the build.

- [Serverless compute](https://www.lindamohamed.com/serverless-compute)

### Amazon S3

Holds the photographs and everything derived from them.

- [Object storage](https://www.lindamohamed.com/object-storage)

### Amazon Athena

Queries the results straight out of S3.
